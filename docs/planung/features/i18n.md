## Was macht dieses Feature?

Hatches unterstützt mehrere Sprachen. Alle UI-Strings werden aus Übersetzungsdateien gelesen. Start: Deutsch (Default) + Englisch. Sprachauswahl per `localStorage` und (später) User-Profil.

## Warum brauchen wir es?

> Als **internationaler Benutzer** möchte ich **Hatches auf Englisch nutzen**,  
> damit ich **die App ohne Sprachbarriere verwenden kann**.

---

## Architektur

### Strategie: Einfache JSON-Übersetzungen (kein i18next)

Kein externes i18n-Framework — eigene, leichtgewichtige Lösung:

```
src/lib/i18n/
├── de.ts        — Deutsche Strings (Default)
├── en.ts        — Englische Strings
└── index.ts     — useTranslation Hook + Language Detection
```

#### `useTranslation` Hook

```typescript
type Language = "de" | "en";

interface TranslationResult {
  t: (key: string, params?: Record<string, string | number>) => string;
  lang: Language;
  setLang: (lang: Language) => void;
}

export function useTranslation(): TranslationResult;

// Verwendung:
const { t, lang, setLang } = useTranslation();
<button>{t("common.save")}</button>
<p>{t("board.cardCount", { count: 5 })}</p>  // "5 Karten"
```

## Technische Entscheidungen

### Warum kein i18next / react-i18next?

- Zu schwer für die Anforderungen
- Kein SSR-Overhead
- Vollständige Kontrolle über das Schlüssel-System
- Einfacher zu debuggen

### Interpolation

```typescript
// Einfache {{key}} Interpolation
t("board.cardCount", { count: 5 })
// de: "{{count}} Karten" → "5 Karten"
// en: "{{count}} cards"  → "5 cards"
```

### Fallback

```typescript
// Fehlender Schlüssel → Key zurückgeben + Warnung in Dev
t("missing.key") → "missing.key" (+ console.warn in dev)
```
